PROJECT OVERVIEW
================================================================================
Robin is an AI-powered tool designed for conducting dark web OSINT (Open Source 
Intelligence) investigations. It combines LLM intelligence with dark web search 
capabilities to help researchers, cybersecurity professionals, and threat 
intelligence analysts investigate threats, find sensitive information, and 
analyze dark web content.

The tool was inspired by Thomas Roccia's "Perplexity of the Dark Web" demo and 
combines multiple OSINT approaches into a unified, user-friendly web interface.

Author: Apurv Singh Gautam
License: MIT (based on LICENSE file presence)
GitHub: https://github.com/apurvsinghgautam/robin

================================================================================
ARCHITECTURE OVERVIEW
================================================================================

The project follows a modular architecture with clear separation of concerns:

1. SEARCH MODULE (search.py)
   - Connects to 16+ dark web search engines via Tor
   - Queries search engines with user queries
   - Deduplicates and returns raw search results

2. SCRAPING MODULE (scrape.py)
   - Downloads and extracts content from .onion URLs
   - Handles Tor proxy connections for privacy
   - Manages resource limits and error handling
   - Supports concurrent scraping with thread pooling

3. LLM INTEGRATION MODULE (llm.py, llm_utils.py)
   - Handles multi-model LLM support (OpenAI, Claude, Gemini, Ollama)
   - Implements query refinement using LLM
   - Filters search results intelligently
   - Generates context-aware summaries

4. USER INTERFACE (ui.py)
   - Streamlit-based web UI
   - Six-stage investigation pipeline
   - Past investigation management and loading
   - Health checks and diagnostics
   - Customizable prompt templates

5. HEALTH & MONITORING (health.py)
   - Tests Tor proxy connectivity
   - Validates LLM provider connections
   - Pings dark web search engines
   - Reports latency and availability metrics

6. CONFIGURATION (config.py)
   - Loads environment variables from .env
   - Validates and cleans configuration values
   - Supports multiple API key providers
   - Handles quoted value parsing

1. search.py - DARK WEB SEARCH ENGINE INTEGRATION
   -----------------------------------------------
   Location: /robin/search.py
   
   Key Components:
   
   a) Dark Web Search Engines (17 total):
      - Ahmia (http://juhanurmihxlp77nkq76byazcldy2hlmovfu2epvl5ankdibsot4csyd.onion/)
      - OnionLand
      - Torgle
      - Amnesia
      - Kaizer
      - Anima
      - Tornado
      - TorNet
      - Torland
      - Find Tor
      - Excavator
      - Onionway
      - Tor66
      - OSS (Open Source Search)
      - Torgol
      - The Deep Searches
      
   b) Main Functions:
      
      get_tor_session():
      - Creates a requests.Session object with SOCKS5 proxy
      - Routes traffic through Tor proxy at 127.0.0.1:9050
      - Implements automatic retry logic with exponential backoff
      - Retries failed requests 3 times before giving up
      
      fetch_search_results(endpoint, query):
      - Sends query to a single dark web search engine
      - Uses rotating user agents to avoid detection
      - Parses HTML response using BeautifulSoup
      - Extracts .onion links from search results
      - Filters out self-referential links and short titles
      - Handles timeout and connection errors gracefully
      - Timeout: 40 seconds per request
      
      get_search_results(refined_query, max_workers=5):
      - Orchestrates parallel searches across all 16 engines
      - Uses ThreadPoolExecutor for concurrent requests
      - Deduplicates results to avoid redundancy
      - Normalizes URLs (removes trailing slashes)
      - Returns list of {title, link} dictionaries
      
   c) Configuration:
      - USER_AGENTS: List of realistic browser user agents for evasion
      - DEFAULT_SEARCH_ENGINES: Array of all 17 search endpoints
      - SOCKS5 proxy configuration for Tor routing
      
   d) Error Handling:
      - Catches connection errors, timeouts
      - Returns empty result set on failure rather than crashing
      - Logs failures at DEBUG level


2. scrape.py - WEB CONTENT EXTRACTION
   -----------------------------------
   Location: /robin/scrape.py
   
   Key Components:
   
   a) Configuration Constants:
      - MAX_DOWNLOAD_BYTES: 1,000,000 bytes (~1MB per page)
      - MAX_EXTRACTED_TEXT_CHARS: 50,000 characters max extracted text
      - MAX_RETURN_CHARS: 2,000 characters in final response
      - ALLOWED_CONTENT_TYPES: text/html, application/xhtml+xml, text/plain
      
   b) Main Functions:
      
      _build_session(use_tor=False):
      - Creates a requests Session with retry logic
      - Configures pool of 20 connections for efficiency
      - Sets up HTTP/HTTPS adapters with automatic retries
      - Optionally routes traffic through Tor proxy
      - Retry strategy: 3 retries, exponential backoff 0.3s
      
      _normalize_url_data(url_data):
      - Extracts and validates URL and title from dict
      - Ensures data is properly formatted
      - Returns tuple (url, title)
      
      _get_session(use_tor=False):
      - Thread-safe session caching using threading.local()
      - Creates separate Tor and direct sessions
      - Reuses sessions to avoid recreation overhead
      
      scrape_single(url_data, rotate=False, rotate_interval=5, 
                   control_port=9051, control_password=None):
      - Scrapes a single URL with robust error handling
      - Automatically detects .onion URLs and uses Tor
      - Sets timeouts: 10-45s for Tor, 5-25s for clearweb
      - Streams download to limit memory usage
      - Stops downloading after 1MB
      - Removes <script> and <style> tags from HTML
      - Normalizes whitespace in extracted text
      - Truncates text to 50,000 characters
      - Returns tuple (url, scraped_text)
      - On failure: returns title only
      
      scrape_multiple(urls_data, max_workers=5):
      - Concurrent scraping of multiple URLs
      - Thread pool size: min(threads, 16)
      - Deduplicates URLs before scraping
      - Truncates final response to 2,000 characters
      - Appends "...(truncated)" suffix if needed
      - Returns dict mapping URL -> scraped_content
      - Graceful failure: missing URLs simply absent from dict
      
   c) Content Processing:
      - Parses HTML with BeautifulSoup
      - Preserves text structure with separator spacing
      - Handles encoding errors with UTF-8 fallback
      - Filters non-HTML content types
      - Limits bandwidth and memory usage
      
   d) Error Handling:
      - Catches connection/timeout errors
      - Returns meaningful fallback on failure
      - Uses DEBUG logging for failures
      - Never raises exceptions (graceful degradation)


3. llm.py - LLM ORCHESTRATION AND ANALYSIS
   ----------------------------------------
   Location: /robin/llm.py
   
   Key Functions:
   
   a) get_llm(model_choice):
      - Resolves model configuration from llm_utils
      - Validates API key presence before instantiation
      - Combines common and model-specific parameters
      - Returns initialized LLM instance
      - Raises ValueError if credentials missing
      
   b) _ensure_credentials(model_choice, llm_class, model_params):
      - Validates that required API keys are set
      - Specific checks for each provider (OpenAI, Anthropic, Google, OpenRouter)
      - Provides clear error messages for missing keys
      
   c) refine_query(llm, user_input):
      Purpose: Optimize user query for dark web search
      System Prompt Role: "Cybercrime Threat Intelligence Expert"
      Process:
      - Analyzes user input query
      - Adds/removes words for better search results
      - Removes logical operators (AND, OR)
      - Limits output to 5 words maximum
      - Returns refined query string
      
      Example:
      Input: "I need to find information about ransomware groups operating in 2024"
      Output: "ransomware groups 2024"
      
   d) filter_results(llm, query, results):
      Purpose: Intelligently select top 20 most relevant search results
      
      Process:
      - Takes all raw search results (could be 100+)
      - Formats results as numbered list with links and titles
      - Sends to LLM with query for context
      - LLM returns comma-separated indices of relevant results
      - Deduplicates while preserving order
      - Caps at 20 results maximum
      
      Error Handling:
      - Catches OpenAI RateLimitError
      - Falls back to truncated format (30-char titles only)
      - If parsing fails, defaults to first 20 results
      
   e) generate_summary(llm, query, content, preset="threat_intel", 
                       custom_instructions=""):
      Purpose: Analyze scraped content and generate investigation summary
      
      Preset Templates:
      1. threat_intel (default):
         - Role: Cybercrime Threat Intelligence Expert
         - Analyzes OSINT data
         - Extracts artifacts: names, emails, phones, crypto addresses, 
           domains, markets, forum names, threat actor info, malware
         - Generates 3-5 key insights
         - Suggests next investigative steps
         
      2. ransomware_malware:
         - Role: Malware and Ransomware Intelligence Expert
         - Focuses on ransomware groups, malware families, exploit kits
         - Identifies file hashes, C2 addresses, staging URLs
         - Maps TTPs to MITRE ATT&CK framework
         - Analyzes victim organizations and sectors
         
      3. personal_identity:
         - Role: Personal Threat Intelligence Expert
         - Focuses on PII exposure: names, emails, SSNs, passport data
         - Identifies breach sources and data brokers
         - Assesses exposure severity
         - Provides protective recommendations
         
      4. corporate_espionage:
         - Role: Corporate Intelligence Expert
         - Analyzes leaked corporate data and espionage activity
         - Identifies threat actors and insider threats
         - Assesses business impact
         - Recommends incident response steps
      
      Output Format:
      - Input Query
      - Source Links Referenced
      - Investigation Artifacts
      - Key Insights (3-5)
      - Next Steps
      
   f) _generate_final_string(results, truncate=False):
      - Formats search results for LLM processing
      - Truncates .onion domains after .onion extension
      - Sanitizes titles (only alphanumeric, dash, period)
      - Optional truncation for rate limit handling
      - Returns numbered list format for LLM parsing

      - gemini-2.5-flash, gemini-2.5-flash-lite

      OpenRouter (Gateway for multiple models):
      - qwen3-80b (free)
      - nemotron-nano-9b (free)
      - gpt-oss-120b (free)
      - gpt-5.1, gpt-5-mini

      - grok-4.1-fast
      
      Ollama (Local models - currently commented out):
      - llama3.2, llama3.1
      - gemma3
      - deepseek-r1
      
   b) Common LLM Parameters:
      - temperature: 0 (deterministic)
      - streaming: True (for real-time output)
      - callbacks: [BufferedStreamingHandler] (for UI updates)
      
   c) BufferedStreamingHandler Class:
      Purpose: Real-time token streaming to Streamlit UI
      
      Methods:
      - __init__(buffer_limit=60, ui_callback=None):
        Initializes with buffer and optional callback
        
      - on_llm_new_token(token, **kwargs):
        Called for each new token from LLM
        Buffers tokens until newline or buffer reaches limit
        Prints to console and calls ui_callback if set
        
      - on_llm_end(response, **kwargs):
        Called when LLM finishes
        Flushes any remaining buffered tokens
      
   d) Model Resolution:
      resolve_model_config(model_choice):
      - Normalizes model name (lowercase, stripped)
      - Looks up in _llm_config_map
      - Returns config dict with class and params
      - Used by both get_llm() and health checks
      
   e) Ollama Integration:
      fetch_ollama_models():
      - Queries Ollama HTTP API for available models
      - Returns empty list if unreachable
      - Dynamically discovers local models
      
      get_model_choices():
      - Builds list of all available models
      - Includes cloud models (if API keys set)
      - Includes local Ollama models (if running)
      - Filters out models with missing credentials


5. health.py - SYSTEM HEALTH AND DIAGNOSTICS
   ------------------------------------------
   Location: /robin/health.py
   
   Key Functions:
   
   a) check_tor_proxy():
      Purpose: Verify Tor SOCKS5 proxy is running
      
      Process:
      - Attempts TCP connection to 127.0.0.1:9050
      - Measures latency in milliseconds
      - Timeout: 5 seconds
      
      Returns:
      {
        "status": "up" | "down",
        "latency_ms": int | None,
        "error": str | None
      }
      
   b) check_llm_health(model_choice):
      Purpose: Test LLM provider connectivity
      
      Process:
      - Resolves model configuration
      - Instantiates LLM
      - Sends minimal test prompt: "Say OK"
      - Measures response latency
      - Validates response is non-empty
      
      Provider Detection:
      - Identifies provider from class name
      - Special handling for OpenRouter vs OpenAI
      - Special handling for local (llama.cpp)
      
      Returns:
      {
        "status": "up" | "down" | "error",
        "latency_ms": int | None,
        "error": str | None,
        "provider": str
      }
      
   c) check_search_engines(max_workers=8):
      Purpose: Test all 16 dark web search engines
      
      Process:
      - Concurrently pings each search engine via Tor
      - Sends dummy query ("test")
      - Measures latency and checks HTTP 200 response
      - Timeout: 20 seconds per engine
      
      Returns:
      List of per-engine status dicts:
      {
        "name": str,
        "status": "up" | "down",
        "latency_ms": int | None,
        "error": str | None
      }
      Sorted in original engine order
      
   d) _ping_single_engine(engine):
      - Helper function for concurrent engine pinging
      - Handles timeout and connection errors
      - Returns engine-specific status dict

8. entrypoint.sh - DOCKER STARTUP SCRIPT
   ----------------------------------------
   Location: /robin/entrypoint.sh
   
   Purpose: Initialize Tor and start Streamlit in Docker
   
   Steps:
   1. Starts Tor daemon in background
   2. Waits for Tor SOCKS5 socket (127.0.0.1:9050)
   3. Timeout: 60 seconds
   4. Verifies socket connectivity with Python
   5. Exits with error if Tor fails to start
   6. Launches Streamlit UI on 0.0.0.0:8501
   
   Environment:
   - Streamlit listens on all interfaces (0.0.0.0)
   - Port exposed: 8501 (default Streamlit)

================================================================================
INVESTIGATION WORKFLOW (DETAILED FLOW)
================================================================================

1. USER ENTERS QUERY
   Input: "find malware source code repositories"
   
2. LLM REFINES QUERY
   Cybercrime Expert Prompt Applied
   Output: "malware source code" (5 words or less)
   
3. PARALLEL SEARCH ACROSS 16 ENGINES
   Each engine receives: "malware+source+code"
   Process:
   - Tor proxy routes request through anonymity network
   - User agent randomized
   - Timeout: 40 seconds
   - HTML parsed for .onion links
   - Self-referential links filtered
   - Deduplication across all 16 results
   
   Output: List of 100-500 unique .onion links
   
4. LLM FILTERS TO TOP 20
   Input: All results (limited to max_results, default 50)
   Process:
   - LLM analyzes relevance of each result
   - Returns comma-separated indices of top 20
   - Deduplicated
   
   Output: 20 most relevant .onion links
   
5. CONCURRENT SCRAPING
   Process:
   - Up to 10 URLs scraped in parallel (configurable)
   - For each URL:
     a. Detect if .onion (yes = use Tor)
     b. Stream download with 1MB limit
     c. Parse HTML and extract text
     d. Clean HTML (<script>, <style> removed)
     e. Limit text to 50,000 characters
     f. Return title + extracted text
   - Deduplication prevents duplicate scraping
   
   Output: Dict of 10 URL -> (title + content)
   
6. LLM ANALYSIS & SUMMARY
   Input:
   - Original query: "find malware source code repositories"
   - Refined query: "malware source code"
   - Scraped content from 10 URLs
   - Preset: threat_intel (or user selection)
   - Custom instructions (optional)
   
   Process:
   - Cybercrime Threat Intelligence Expert role
   - Analyzes all content for:
     * Source links
     * Investigation artifacts (names, emails, domains, etc.)
     * Key insights (3-5 points)
     * Next investigation steps
   - Streams output token-by-token to UI
   
   Output:
   Structured Report:
   1. Input Query
   2. Source Links Referenced
   3. Investigation Artifacts
   4. Key Insights
   5. Next Steps
   
7. SAVE INVESTIGATION
   Process:
   - Create investigations/investigation_20250429_143025.json
   - Store all query stages, model, sources, summary
   - Enable loading in "Past Investigations"
   
8. USER DOWNLOADS SUMMARY
   Format: Markdown (.md)
   Filename: summary_YYYY-MM-DD_HH-MM-SS.md
   Downloaded via browser
   
9. USER LOADS PAST INVESTIGATION
   Process:
   - Sidebar shows all investigations
   - Click "Load" to restore in main area
   - View all details without re-running

2. USER AGENT ROTATION
   - Randomly selected from pool of 9 browsers

   - Never logged or displayed in UI

   - Loaded from environment only
   - Clear error messages if missing (but don't expose key)

   - Scraped content not stored (only in JSON investigations)
   - Session-based caching (200 seconds)
   - Investigations stored as local JSON
   - Downloaded reports are user responsibility

5. RATE LIMITING
   - Respects HTTP 429 (rate limit) responses
   - Automatic retry with backoff
   - LLM rate limits handled with fallback
   - Search engine timeouts gracefully handled

6. RESOURCE LIMITS
   - Max download size: 1MB (prevents DoS)
   - Text extraction capped: 50,000 chars
   - Max results returned: 2,000 chars
   - Prevents memory exhaustion

Issue: "Tor failed to start or is not listening"
Solution:
- Verify Tor is running: sudo systemctl status tor
- Check port 9050: netstat -ln | grep 9050
- Restart Tor: sudo systemctl restart tor

Issue: "ANTHROPIC_API_KEY is not set"
Solution:
- Add to .env: ANTHROPIC_API_KEY=sk-ant-...
- Restart Streamlit app: Ctrl+C, streamlit run ui.py

Issue: "No LLM models available"
Solution:
- Set at least one API key in .env
- Restart app
- Reload browser page

Issue: "0/16 engines reachable"
Solution:
- Check Tor proxy is running
- Verify network connectivity
- Try from another network
- Some engines may be temporarily down

Issue: "Rate limit error"
Solution:
- Wait a few minutes before next search
- LLM will automatically fall back to truncated format
- Consider using OpenRouter free models
